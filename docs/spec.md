# 资源分享站 · 云端版规格书

本机版继续保留，这份规格描述部署到 Cloudflare 的版本。

## 1. 为什么要云端版

本机版的限制很明确：电脑得开着、同一个 Wi-Fi、外网访问不了。云端版要解决的是"我不开电脑，别人也能访问"。

## 2. 技术选型

| 用途 | 选型 | 说明 |
| --- | --- | --- |
| 页面与接口 | Cloudflare Workers | 一个 `fetch` 处理器，不再有 `http.createServer` |
| 文件 | R2（默认）/ Workers KV（备用） | 取代本机版的 `uploads/`；两者都不需要自建服务器 |
| 账号与资源数据 | D1 | 取代本机版的 `data/db.json` |
| 登录状态 | D1 里的 sessions 表 | 无状态环境不能靠内存记会话 |

`node:crypto` 在 Workers 里可用（scrypt 不在不支持名单内），所以口令哈希逻辑可以照搬本机版。

## 3. 角色模型

三种角色，权限写死在 `src/core/roles.js` 里，不散落到接口中。

| | 管理员 | 成员 | 游客 | 没登录 |
| --- | --- | --- | --- | --- |
| 看「所有人可见」的资源 | ✓ | ✓ | ✓ | ✓ |
| 看「登录可见」的资源 | ✓ | ✓ | ✓ | ✗ |
| 上传文件 | ✓ | ✓ | ✗ | ✗ |
| 删除自己的文件 | ✓ | ✓ | ✗ | ✗ |
| 删除别人的文件 | ✓ | ✗ | ✗ | ✗ |
| 生成邀请码 | ✓ | ✗ | ✗ | ✗ |

游客是只读的：能看全部资源，但不能上传，也不能删东西。

**为什么把"没登录"单独列出来**：早先匿名访客和 guest 共用一个角色定义，
结果 guest 能做的事和"不给账号"完全一样 —— 那个邀请选项等于白给。
现在两者分开：匿名只能看公开资源，有账号（哪怕是游客）才能看「登录可见」的资源。

## 4. 邀请码机制

关闭自由注册。注册时必须提供有效邀请码。

- 码长 10 位，字符集去掉容易看错的 `0 O 1 I L`
- 展示时每五位加一个横线：`ABCDE-FGHIJ`
- 输入时忽略大小写、空格和横线
- 每个码记录：角色、可用次数、已用次数、过期时间、是否作废、创建者
- 失效原因分四种并分别提示：不存在 / 已作废 / 已过期 / 已用完

管理员可以在后台生成邀请码，指定角色和有效期。

## 5. 口令安全

注册和改密码时都过同一套规则（`src/core/password.js`），**一次列出全部问题**，而不是改一个报一个。

- 长度至少 8 个字符
- 不能是常见弱口令（内置一份短名单）
- 不能全是数字
- 不能包含昵称，也不能被昵称包含

### 登录失败限制

- 15 分钟内失败 5 次即锁定，锁定同样 15 分钟
- 提示还剩多少分钟，不透露账号是否存在

### 其它

- 口令用 scrypt 加盐哈希，比对用定时安全比较
- 会话存 D1，带过期时间；退出即删除
- 改密码后，该用户的所有其它会话立即失效

## 6. 资源可见性

每份资源带一个 `visibility`：

- `public` —— 游客也能下载，默认值
- `members` —— 只有成员和管理员能下载

列表接口按角色过滤：游客拿不到 `members` 的资源，直接访问下载地址同样会被拒（**服务端拦，不是前端藏**）。

## 7. 上传大小

- 经过 Worker 的上传受 Cloudflare 请求体上限约束（免费版 100MB），谁都一样，包括管理员
- 本机版不受此限，上限由配置决定

### 大文件方案

浏览器把文件切开，逐片发给 Worker，由 Worker 写进存储，绕开请求体上限。
分片大小按后端取：R2 是 25MB（R2 要求除最后一片外每片不小于 5MB），
KV 是 2MB（KV 单值上限 25MB）。

文件存哪由 `FILE_BACKEND` 决定，不填就是 R2。

## 8. 数据模型

```
users      id, username, password_hash, salt, role, created_at, disabled_at
invites    code, role, max_uses, used_count, expires_at, revoked_at, created_by, created_at
resources  id, owner_id, title, description, category, platform,
           visibility, r2_key, file_name, file_size, mime, downloads, created_at
sessions   token, user_id, created_at, expires_at
login_failures  username, occurred_at
```

R2 的对象键：`u/<ownerId>/<resourceId><扩展名>`，按上传者分目录。

## 9. 接口

沿用本机版的形状，只增不改：

```
POST /api/register          需带邀请码
POST /api/login
POST /api/logout
GET  /api/me
POST /api/password          改密码（新）
GET  /api/resources
POST /api/upload
DELETE /api/resources/:id
GET  /api/download/:id
GET  /api/admin/invites     管理员（新）
POST /api/admin/invites     管理员（新）
GET  /api/admin/users       管理员（新）
```

## 10. 明确不做

- 大文件分块直传（第二阶段）
- 邮箱验证、密码找回
- 资源在线预览
- 操作审计日志
- 评论、点赞

## 8. 后续追加（第四批）

| 编号 | 需求原话 | 说明 |
| --- | --- | --- |
| R14 | 点到注册框外会关闭页面，这点改掉；密码要输两次对照；最少 8 位 | 见下面的验收标准 |

### R14 的验收标准

- **点击弹窗外的区域不再关闭弹窗** —— 表单填一半被误关掉，代价太大。关闭方式保留：右上角 ✕、取消按钮、Esc
- **注册时输入两次密码**，不一致就拦下来并提示，不提交
- **口令长度下限 8 位**，上限 200 位不变


## 9. 后续追加（第五批）

| 编号 | 需求原话 | 说明 |
| --- | --- | --- |
| R15 | 管理员需要一个地方查看每个文件的来源是谁，并且能对文件进行编辑，比如换位置 | 管理面板加"资源管理"页签 |

### R15 的验收标准

- 管理面板分「邀请码」和「资源管理」两个页签
- 资源管理列表每条显示：标题、上传者、分类、可见范围、大小、下载次数、上传时间
- 点「编辑」能改标题、简介、分类（即"换位置"）、运行平台、可见范围
- 权限：管理员能改任何人的，成员只能改自己的，游客不能改
- 改分类之后，新分类的列表里能看到它，旧分类里不再出现
- 只传部分字段时，其余字段保持原样（尤其是下载次数不能被抹掉）
